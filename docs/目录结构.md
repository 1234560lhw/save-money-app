# 目录结构说明

本文说明每个文件夹放什么、为什么这样分，以及新增代码该放哪里。

---

## 1. 总览

```
save-money-app/
├── core/                     共享核心（无界面）
├── apps/                     两个前端（共用 core 与 _shared）
│   ├── _shared/                 共享 UI
│   ├── desktop/                 桌面端入口
│   └── mobile/                  手机端入口
├── tests/                    测试（纯数据，不需要界面）
├── scripts/                  开发脚本（不参与打包运行）
├── docs/                     文档
├── config/                   本机配置（pip 镜像等）
├── assets/                   图标等静态资源（打包时用）
├── .venv/                    专用虚拟环境
├── .devdata/                 开发期数据库（--dev 时生成）
├── requirements.txt          运行依赖
└── requirements-desktop.txt  桌面/浏览器预览额外依赖
```

---

## 2. 为什么分 `core` 和 `apps`

需求是"以后要分成电脑软件和手机 App 两个"。如果两端各写一套代码，
最容易出现的是**同一条流水在两端算出的储蓄率不一样**——这是记账软件最致命的 bug。

所以按"计算与界面分离"来分：

```
        ┌──────────────── core/（算钱、存数据）────────────────┐
        │  models · errors · db/ · services/ · utils/          │
        └───────────────▲──────────────────────▲───────────────┘
                        │                      │
        ┌───────────────┴──────┐   ┌───────────┴──────────────┐
        │ apps/desktop         │   │ apps/mobile              │
        │  app_entry.py        │   │  app_entry.py            │
        │  窗口尺寸/数据目录     │   │  全屏/应用私有目录         │
        └───────────┬──────────┘   └───────────┬──────────────┘
                    │                          │
                    └──────► apps/_shared ◄────┘
                           （界面代码只有一份）
```

* **`core/` 里没有一行 Flet 代码**，因此可以用纯测试覆盖（见 `tests/`）；
* **两个入口的差异只有 20 行左右**：窗口尺寸、标题、数据目录、默认视图模式；
* 界面本身也是共享的，所以两端功能天然一致，不会一边有一边没有。

---

## 3. `core/` 内部怎么分

| 目录 / 文件 | 放什么 | 不放什么 |
| --- | --- | --- |
| `models.py` | 数据模型（`Transaction` / `Category` / `GoalProgress` / `MonthlySummary`） | 不放查询语句 |
| `errors.py` | 统一异常基类 `AppError` 及其子类 | 不放业务逻辑 |
| `bootstrap.py` | 启动引导：import 路径、初始化数据库 | 不放界面 |
| `db/connection.py` | 连接管理、事务、热备份 | 不写业务查询 |
| `db/schema.py` | 建表 SQL、版本迁移、预置分类 | 不做增删改 |
| `db/repositories/` | 每张表一个仓储：增删改查 + 字段校验 | 不做跨表统计 |
| `services/` | 跨表业务计算：储蓄率、目标进度、导入导出 | 不碰控件 |
| `utils/money.py` | 金额解析、格式化、安全除法 | 不查数据库 |
| `utils/paths.py` | 数据目录、数据库路径、备份目录 | 不写业务数据 |
| `utils/tempfix.py` | 受限环境下的临时目录兼容补丁 | 与业务无关 |

### 分层调用规则

```
界面 (apps/_shared)
   │  只能往下调用
   ▼
services（算钱）
   │
   ▼
repositories（存取）
   │
   ▼
connection / schema（SQLite）
```

**禁止反向调用**：`core` 里不允许 `import flet`，也不允许 import `_shared`。
这样测试才能脱离界面跑得飞快。

## 4. `apps/_shared/` 内部怎么分

| 文件 / 目录 | 放什么 |
| --- | --- |
| `theme.py` | 颜色、间距、圆角、字号、明暗主题、`Palette` 语义色 |
| `shell.py` | `AppShell`：底部导航 4 标签、页面懒加载、全局刷新 |
| `components.py` | 可复用小组件：金额文本、指标块、目标卡片、流水行、空状态、确认框 |
| `views/base.py` | `BaseView`：页面契约（`load()` / `render()`）与错误兜底 |
| `views/home.py` | 首页仪表盘 |
| `views/add_transaction.py` | 记一笔 |
| `views/transactions.py` | 流水列表 |
| `views/edit_transaction.py` | 单条流水编辑 / 删除弹窗 |
| `views/settings.py` | 设置页 + 目标编辑弹窗 + 分类编辑弹窗 |

**新增页面怎么做**：

1. 在 `views/` 下新建文件，继承 `BaseView`；
2. 实现 `load()`（从 services 取数，存到 `self` 上）和 `render()`（排版）；
3. 在 `views/__init__.py` 导出；
4. 在 `shell.py` 的 `TABS` 与 `_create_view()` 里登记。

数据改动后调用 `self.changed("已保存")`，页面会自动刷新（通过 `AppShell.notify_data_changed`）。

---

## 5. 目录与文件命名约定

* 目录与模块名用小写 + 下划线：`transaction_repo.py`、`goal_service.py`；
* 以 `_` 开头的目录表示"内部实现，外部不要直接 import"：`apps/_shared`；
* 仓储统一叫 `xxx_repo.py`，服务统一叫 `xxx_service.py`；
* 一个文件只放一类东西：`edit_transaction.py` 只放流水编辑弹窗。

---

## 6. 哪些不该提交到版本库

见根目录 `.gitignore`，重点是：

* `.venv/`、`__pycache__/`、`*.pyc`：环境与缓存；
* `.devdata/`、`.tmp/`：开发期数据与临时文件；
* `build/`、`dist/`：打包产物；
* `*.db`、`*.db-wal`、`*.db-shm`：真实账本数据，**绝对不要提交**。

---

## 7. 数据文件在哪

| 场景 | 位置 |
| --- | --- |
| 正式使用（Windows） | `%APPDATA%\SaveMoneyApp\pocket_money.db` |
| 正式使用（macOS） | `~/Library/Application Support/SaveMoneyApp/` |
| 正式使用（Linux） | `~/.local/share/SaveMoneyApp/` |
| 手机 App | 应用私有数据目录 |
| 开发（`--dev`） | `<项目>/.devdata/pocket_money.db` |

同目录下还有：

* `backups/` —— 导出的 .db 备份、CSV、导入前的自动快照；
* `exports/` —— 预留的导出目录。

跨设备迁移就是把 `backups/` 里的 `.db` 拷到新设备再导入。
